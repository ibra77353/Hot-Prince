# Prince Net — بوابة شبكة البرنس نت

## نبذة عن المشروع

**Prince Net** هو مشروع واجهة ويب لبوابة شبكة إنترنت تعتمد على نظام **MikroTik Hotspot**. يضم ملفات صفحات البوابة والموارد اللازمة لعرض واجهة المستخدم والتعامل مع الوظائف المرتبطة بتسجيل الدخول، وحالة الاتصال، والخروج، وإعادة التوجيه، إضافةً إلى مكونات JavaScript مساعدة وخدمات واجهة أخرى موجودة ضمن المشروع.

يهدف المشروع إلى توفير نقطة دخول موحدة لمشتركي الشبكة، وتنظيم صفحات البوابة وملفاتها في بنية واضحة يمكن مراجعتها وتخصيصها وصيانتها.

> **تنبيه مهم:** هذا المستودع يحتوي على ملفات الواجهة الأمامية ومواردها. وجود صفحة أو ملف JavaScript لا يثبت وحده أن الوظيفة المرتبطة به تعمل بالكامل؛ إذ يعتمد التشغيل الفعلي على محتوى الملفات، وإعدادات MikroTik Hotspot، والخدمات التي تتصل بها الصفحة. يجب اختبار الوظائف في بيئة الشبكة المستهدفة.

## لمن هذا المشروع؟

المشروع مناسب للفئات التالية:

- **أصحاب شبكات الإنترنت المحلية** الذين يستخدمون بوابة Hotspot ويريدون تنظيم صفحات دخول المشتركين.
- **مسؤولو شبكات MikroTik** الذين يحتاجون إلى مراجعة ملفات بوابة الدخول وتخصيصها بما يتوافق مع إعدادات شبكتهم.
- **فنيو ومطورو الويب** الذين يعملون على صفحات Hotspot باستخدام HTML وCSS وJavaScript.
- **مشغلو نقاط بيع بطاقات الإنترنت** إذا كانت وظائف البيع أو عرض الباقات المطلوبة مدعومة بالفعل في ملفات المشروع وإعدادات الشبكة.
- **فرق الدعم والصيانة** التي تحتاج إلى فهم بنية الملفات ومواقع الصفحات والموارد قبل تعديلها.

## ما الذي يحتوي عليه المشروع؟

وفقًا لبنية الملفات الحالية، يتضمن المستودع ما يلي:

### 1. صفحات بوابة الشبكة

- `index.html` — الصفحة الرئيسية للبوابة.
- `login.html` — صفحة تسجيل الدخول.
- `alogin.html` — صفحة دخول إضافية مرتبطة بتدفق المصادقة في البوابة.
- `logout.html` — صفحة تسجيل الخروج.
- `status.html` — صفحة حالة المستخدم أو الاتصال.
- `redirect.html` — صفحة إعادة التوجيه.

تحدد ملفات HTML هيكل الصفحات ومحتواها، بينما تعتمد التفاصيل الوظيفية على الشيفرة الموجودة داخلها والملفات التي تستدعيها.

### 2. ملفات JavaScript

يوجد مجلد `js/` ويحتوي على:

- `init.min.js` — ملف تهيئة.
- `main.min.js` — ملف JavaScript رئيسي.
- `hotInImprover.min.js` — ملف مساعد مرتبط بتحسينات واجهة الدخول.
- `hotCookie.min.js` — ملف مرتبط بالتعامل مع ملفات تعريف الارتباط (Cookies).
- `hotOptions.min.js` — ملف مرتبط بخيارات أو إعدادات الواجهة.
- `hotBlocker.min.js` — ملف مرتبط بوظائف الحظر.
- `loan.min.js` — ملف مرتبط بمكوّن المحفظة أو وظيفة السلفة بحسب التطبيق.
- `mus.min.js` — ملف JavaScript إضافي.
- `store.min.js` — ملف JavaScript إضافي مرتبط بالمتجر أو مكوناته.
- `templates.min.js` — ملف مرتبط بالقوالب.

الأسماء السابقة توضح الغرض المحتمل من الملفات، لكنها ليست بديلًا عن مراجعة محتواها. لا يمكن تأكيد وظيفة كل ملف أو اكتمالها من الاسم وحده.

### 3. ملفات CSS

يوجد مجلد `css/` ويحتوي على:

- `style.min.css` — التنسيقات الأساسية.
- `mhtrf.css` — تنسيقات إضافية.
- `mawlid.css` — ملف تنسيقات إضافي.
- `responsive-mawlid.css` — تنسيقات مرتبطة باستجابة الواجهة لأحجام الشاشات.
- `speed.css` — تنسيقات مرتبطة بقسم السرعات أو العناصر التي تحمل هذا الاسم.
- `fontello.min.css` — تنسيقات الأيقونات.
- `sweetalert2.min.css` — تنسيقات نوافذ التنبيه الخاصة بـ SweetAlert2.

تتحكم هذه الملفات في مظهر العناصر وترتيبها وطريقة عرضها. وقد يعتمد بعضها على ملفات الخطوط أو الأيقونات الموجودة في مجلدات أخرى.

### 4. الإعدادات

- `config/config.js` — ملف إعدادات JavaScript. ينبغي مراجعة محتواه لمعرفة القيم التي يضبطها والخدمات أو المسارات التي يعتمد عليها.

لا تُدرج كلمات المرور أو الرموز السرية أو بيانات الوصول الخاصة داخل مستودع عام.

### 5. الخطوط

يتضمن مجلد `fonts/`:

- `Almarai.css`
- `Almarai.woff2`
- `fontello.woff2`

تُستخدم هذه الملفات لتوفير الخطوط والأيقونات التي تشير إليها ملفات CSS.

### 6. الصور والأيقونات

يتضمن مجلد `img/`:

- `favicon.ico` — أيقونة الموقع.
- `jaib.webp` — صورة بصيغة WebP.
- `pic1.jpg`
- `pic2.jpg`

كما يحتوي `app_store/icon/` على الأيقونتين `1.png` و`2.png`، ويمكن أن تُستخدم هذه الصور في المكونات التي تشير إليها.

### 7. التوثيق

- `README-AR.txt` — ملف توثيق عربي موجود ضمن المشروع.
- `README.md` — ملف التوثيق الرئيسي على GitHub، ويشرح هدف المشروع وبنيته وطريقة مراجعته وتشغيله.

## التقنيات وبيئة التشغيل

توضح امتدادات الملفات أن المشروع يستخدم تقنيات الويب التالية:

- **HTML** لبناء الصفحات.
- **CSS** لتنسيق الواجهة.
- **JavaScript** لإضافة التفاعلات والوظائف في المتصفح.
- **Web Fonts** للخطوط والأيقونات.

المشروع لا يتطلب إطار عمل مثل React أو Laravel لمجرد عرض صفحات HTML وCSS وJavaScript. لكن تشغيل وظائف Hotspot الفعلية يتطلب بيئة متوافقة مع إعدادات الشبكة والملفات المستخدمة.

## طريقة المعاينة محليًا

1. نزّل المستودع أو استخرج ملف ZIP الخاص به.
2. حافظ على المجلدات والمسارات النسبية كما هي.
3. افتح `index.html` في متصفح لمعاينة الصفحة.
4. إذا كانت بعض الوظائف تعتمد على متغيرات أو مسارات أو خدمات يوفرها MikroTik Hotspot، فقد لا تعمل عند فتح الملف مباشرةً من الكمبيوتر.
5. للتحقق من السلوك الكامل، اختبر الصفحات في بيئة Hotspot متوافقة مع إعدادات المشروع.

## الاستخدام مع MikroTik Hotspot

قبل استخدام الملفات على شبكة فعلية:

1. راجع محتوى صفحات HTML وملفات JavaScript وملف `config/config.js`.
2. تحقق من متغيرات Hotspot وحقول تسجيل الدخول ومسارات الملفات التي تعتمد عليها الصفحات.
3. تأكد من وجود جميع الموارد المشار إليها، بما فيها ملفات CSS والخطوط والصور وJavaScript.
4. تحقق من أن آلية المصادقة وإعادة التوجيه وتسجيل الخروج متوافقة مع إعدادات جهاز MikroTik.
5. اختبر صفحات الدخول والحالة والخروج وإعادة التوجيه والوظائف الإضافية في بيئة الشبكة المستهدفة.

لا يمكن ضمان توافق جميع الملفات مع كل إصدارات RouterOS أو كل إعدادات Hotspot دون اختبار فعلي.

## استكشاف الأخطاء

إذا لم تعمل الصفحة أو إحدى وظائفها:

- افتح أدوات المطور في المتصفح، ثم راجع تبويب **Console** للأخطاء.
- راجع تبويب **Network** للتحقق من تحميل ملفات CSS وJavaScript والصور.
- تحقق من صحة المسارات وحالة الأحرف وأسماء الملفات.
- تأكد من تحميل جميع الملفات المطلوبة وعدم حذف أي ملف تستخدمه صفحة أخرى.
- عند الاختبار داخل Hotspot، راجع إعدادات صفحة الدخول والمصادقة وإعادة التوجيه في MikroTik.
- افحص محتوى ملف الإعدادات والسكربتات قبل تغيير أي قيمة غير واضحة.

## حدود التوثيق وحالة الاختبار

هذا الملف يوثق بنية المشروع استنادًا إلى أسماء الملفات والمجلدات الموجودة. أما تفاصيل الوظائف الداخلية، والاتصالات الخارجية، وآلية المصادقة، وتوافق كل صفحة مع إعدادات الراوتر، فتحتاج إلى مراجعة الشيفرة واختبارها.

لا يُعد وجود ملف باسم معين دليلًا على أن الوظيفة المقابلة مكتملة أو مختبرة. لذلك يجب عدم اعتبار المشروع جاهزًا للتشغيل الفعلي قبل التحقق من الوظائف المطلوبة في البيئة المستهدفة.

## المساهمة والتطوير

عند تعديل المشروع:

- احتفظ ببنية المجلدات والمسارات التي تعتمد عليها الصفحات.
- عدّل الملف المسؤول عن الوظيفة المطلوبة بعد مراجعة مراجعته واستخداماته.
- اختبر الصفحات المتأثرة بعد كل تعديل.
- لا تحذف ملفات JavaScript أو CSS لمجرد أن أسماءها غير واضحة؛ تحقق أولًا مما إذا كانت الصفحات تستدعيها.
- وثّق أي إعداد جديد أو متطلب إضافي في هذا الملف.
